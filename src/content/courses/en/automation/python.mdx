## Setting up the environment

Always work in a **virtual environment** (venv): a folder holding its own version of the libraries,
isolated from the system. Each project has its own, with no conflicts.

```bash
cd netops
python3 -m venv .venv
source .venv/bin/activate        # repeat in every new terminal
pip install -r requirements.txt
```

<CodeFile lab="netops" file="requirements.txt" />

Finally, the service account credentials go in **environment variables**:

```bash
export NET_USER=svc-netops
export NET_PASSWORD='netops-lab'
```

<Callout type="warning">
A password is **never** written in a script or in a Git repository, even a private one: it always ends up
leaking (a screenshot, a repo made public, a former colleague). Read it from the environment, from a vault
(Ansible Vault, HashiCorp Vault…) or from a pipeline's masked variables. The lab scripts refuse to start if
the variables are missing.
</Callout>

## Netmiko: driving the CLI over SSH

**Netmiko** connects over SSH just like you would, handles prompts, paging and configuration mode, and
returns the output as text. It knows dozens of platforms (Arista, Cisco, Juniper, Fortinet, Palo Alto…),
selected with the `device_type` parameter.

```python
from netmiko import ConnectHandler

switch = {"device_type": "arista_eos", "host": "172.20.30.12", "username": "svc-netops", "password": "…"}

with ConnectHandler(**switch) as conn:
    print(conn.send_command("show ip interface brief"))            # a "show" command
    conn.send_config_set(["vlan 40", "name MANAGEMENT"])           # enters configuration mode
    conn.save_config()                                             # write memory
```

The `with` block closes the connection cleanly, even when an error occurs.

## Usable output: JSON

Text output is made for humans. A script has to cut it up ("parse" it), which is fragile: one column moves
between versions and everything breaks. Arista EOS can answer directly in **JSON** when you append `| json`
to any command:

```text title="leaf1#show version | json (excerpt)"
{
    "modelName": "cEOSLab",
    "version": "4.32.0F",
    "serialNumber": "5A1B2C3D4E5F",
    "uptime": 5329.77,
    ...
}
```

In Python, `json.loads()` turns this text into a dictionary: `data["version"]` gives the version directly,
without any regular expression.

<Callout type="tip">
On platforms that cannot answer in JSON (part of the Cisco IOS fleet, for example), Netmiko can parse the
output with ready-made **TextFSM** templates: `conn.send_command("show ip interface brief", use_textfsm=True)`
returns a list of dictionaries.
</Callout>

## Working in parallel

## Handling errors

A powered-off device, a changed password: on a large fleet, there is **always** one device that doesn't
answer. A good script reports it, carries on with the others and ends with a non-zero exit code, so that a
pipeline knows something went wrong. Netmiko raises specific exceptions:

| Exception | Means |
|---|---|
| `NetmikoTimeoutException` | the device doesn't answer (powered off, routing, port 22 filtered) |
| `NetmikoAuthenticationException` | username or password rejected |

## Other libraries

| Library | Principle | When to use it |
|---|---|---|
| **Netmiko** | CLI over SSH, multi-vendor | the Swiss army knife, perfect to get started |
| **pyeapi** | Arista's JSON <Term id="api" /> (eAPI) | 100 % Arista fleet, guaranteed structured output |
| **Scrapli** | CLI over SSH, faster, async available | large volumes, performance |
| **NAPALM** | a common interface (getters, config replace) | multi-vendor tools |
| **ncclient** | NETCONF | devices driven by YANG models |
| **Nornir** | a framework: inventory, parallel execution, Netmiko / NAPALM / Scrapli plugins | replacing Ansible with plain Python, when logic gets complex |

## Key takeaways

- Always a **virtual environment**, and **never** a password in the code.
- **Netmiko** drives the CLI over SSH: `send_command`, `send_config_set`, `save_config`.
- Prefer **structured** output: `| json` on Arista, TextFSM elsewhere.
- A YAML **inventory** shared with Ansible, a **thread pool** for parallelism.
- Handle errors: report, carry on, and finish with an explicit **exit code**.

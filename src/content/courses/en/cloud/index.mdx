The path started with a cable and an Ethernet frame. It ends where many applications now live: in the
**public cloud**. A cloud network is configured through an API rather than a CLI, but everything the
previous hops built is still there: an addressing plan, route tables, firewalls, BGP, IPsec tunnels and
versioned code. This hop shows what stays the same, what really changes, and how to connect the cloud to
the data center properly.

## The common thread: the company moves into the Paris region

The company from the previous courses deploys its new applications on **AWS**, in the `eu-west-3` (Paris)
region. The network has to follow: a well-structured VPC, filtering as strict as in the data center, several
VPCs talking to each other without turning into spaghetti, a reliable link to the data center, and all of
it described as code.

## What you will learn

| Chapter | What you will be able to do |
|---|---|
| **1. AWS networking basics** | Split a VPC into public and private subnets, route to the Internet, understand what differs from a LAN |
| **2. Security groups and NACLs** | Filter with and without state, reference groups rather than addresses, troubleshoot with VPC Flow Logs |
| **3. Interconnecting VPCs** | Choose between peering, Transit Gateway and PrivateLink, and segment with route tables |
| **4. Hybrid cloud** | Build a site-to-site VPN with BGP, understand Direct Connect, control the path traffic takes |
| **5. Network as code with Terraform** | Describe the whole network as code, manage state, and deploy through a pipeline |

Examples use **AWS**, the most widespread. Each chapter points out the **Azure** and **Google Cloud**
equivalents: names change, principles stay.

## The lab: Terraform, not ContainerLab

A VPC can't be emulated in a container: this hop's lab is a set of <Term id="iac">Terraform</Term> files
that builds a real network in **your AWS account**. It is designed to cost nothing by default: VPCs,
subnets, route tables, Internet Gateways, security groups and NACLs are not billed.

```bash title="Get the lab"
mkdir cloud-aws && cd cloud-aws
for f in versions.tf variables.tf vpc.tf security.tf vpn.tf outputs.tf terraform.tfvars.example; do
  curl -fsSL -o "$f" "https://nexthop.alcpt.network/labs/cloud-aws/$f"
done
```

Comments and descriptions in the lab files are in French.

<Callout type="warning">
Some resources are **billed by the hour**, whether used or not: the NAT Gateway, Transit Gateway attachments,
VPN connections, and every public IPv4 address. Expect a few cents per hour per resource, which adds up to
tens of dollars a month if you forget them. In the lab they are disabled by default (`enable_nat_gateway`,
`enable_vpn`…). Enable them for the duration of an exercise, then **always** run `terraform destroy` at the
end of the session. Also create a **budget alert** (*Billing > Budgets*) as soon as the account is open, and
check the free offer's terms on the *AWS Free Tier* page: they change regularly.
</Callout>

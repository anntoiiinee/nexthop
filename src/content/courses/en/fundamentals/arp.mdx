We now have two kinds of addresses: the **IP** address to know **where** to go (layer 3), and the
**MAC** address to deliver the frame on the local network (layer 2). But when PC1 wants to reach
`192.168.10.20`, it only knows its IP. To build the Ethernet frame, it needs its MAC. The protocol
that links the two is <Term id="arp" /> (RFC 826).

Without a destination MAC address, there is no frame, and therefore no communication, even within the
same network. ARP exists to answer exactly one question: "**which MAC owns this IP?**"

## The ARP exchange

ARP works in two steps:

1. **The request**, sent as a **broadcast** (`ff:ff:ff:ff:ff:ff`): every machine in the VLAN receives
   it. It says: "Who has 192.168.10.20? Tell 192.168.10.10".
2. **The reply**, sent as **unicast** by the only machine concerned: "192.168.10.20 is me, my MAC is
   `02:00:00:00:00:20`".

Along the way, everyone learns something:

- **PC1** stores PC2's MAC in its **ARP cache**;
- **PC2** also stores PC1's MAC (it is in the request): it will need it to reply;
- **the switch** learns PC1's location from the request, and PC2's from the reply.

## The ARP packet

An ARP message is carried directly inside an Ethernet frame, with EtherType `0x0806`. There is no IP
header: ARP works **only inside a local network**.

| Field | PC1's request | PC2's reply |
|---|---|---|
| Destination MAC (Ethernet) | `ff:ff:ff:ff:ff:ff` (broadcast) | `02:00:00:00:00:10` (PC1) |
| Operation | 1 (request) | 2 (reply) |
| Sender MAC | `02:00:00:00:00:10` | `02:00:00:00:00:20` |
| Sender IP | `192.168.10.10` | `192.168.10.20` |
| Target MAC | `00:00:00:00:00:00` | `02:00:00:00:00:10` |
| Target IP | `192.168.10.20` | `192.168.10.10` |

## The ARP cache

Sending a request before every packet would be very slow. Every machine therefore keeps the replies
in an **ARP cache** (or neighbor table), with a limited lifetime:

```text title="Linux: ip neigh"
192.168.10.1 dev eth1 lladdr 00:1c:73:aa:bb:01 REACHABLE
192.168.10.20 dev eth1 lladdr 02:00:00:00:00:20 STALE
192.168.10.99 dev eth1 FAILED
```

```text title="Windows: arp -a"
Interface: 192.168.10.10 --- 0x7
  Internet Address      Physical Address      Type
  192.168.10.1          00-1c-73-aa-bb-01     dynamic
  192.168.10.20         02-00-00-00-00-20     dynamic
```

```text title="R1#show ip arp"
Address         Age (sec)  Hardware Addr   Interface
192.168.10.10     0:01:12  0200.0000.0010  Ethernet1
192.168.10.20     0:00:45  0200.0000.0020  Ethernet1
192.168.10.121    0:03:02  001c.73cc.dd02  Ethernet2
```

Lifetimes vary a lot: from a few seconds to a few minutes on Linux and Windows (which regularly
re-check their entries), **4 hours** by default on Cisco and Arista routers and switches. A `FAILED`
(Linux) or `Incomplete` (Cisco) entry means a request was sent but **nobody answered**.

<Callout type="tip">
`ip neigh flush all` (Linux) or `arp -d *` (Windows, as administrator) clear the cache. Useful after
replacing a network card or moving an IP address from one machine to another.
</Callout>

## What if the destination is in another network?

This is the point that trips up the most beginners: **a machine never ARPs for an address that is not
in its own network.** An ARP request is a broadcast; it doesn't cross routers. To reach
`172.16.20.10` at headquarters, PC1 sends an ARP request for its **gateway**:

The frame sent will therefore have **R1's MAC** as its destination, and `172.16.20.10` as its
destination IP. We cover this in detail in the next chapter on routing, where each router does the
same thing again with the next hop.

## Gratuitous ARP

A **gratuitous ARP** is an announcement nobody asked for: a machine broadcasts "192.168.10.1 is me, my
MAC is …". It is used:

- **at boot or when an address changes**: to check that nobody else already uses this IP (conflict
  detection);
- **during a redundant gateway failover** (<Term id="vrrp" />, HSRP): the router becoming active
  announces the gateway IP address with its own MAC. Every machine updates its cache, and every switch
  its MAC table, without waiting for entries to expire.

## ARP's weakness: spoofing

ARP dates back to 1982 and has **no authentication**: a machine accepts an ARP reply without checking
who sent it, even if it never asked. An attacker inside the VLAN can therefore send fake replies:
this is **ARP spoofing** (or poisoning):

The protections, on access switches:

- **DHCP Snooping**: the switch watches <Term id="dhcp" /> exchanges and remembers which IP was handed
  to which MAC, on which port;
- **Dynamic ARP Inspection (DAI)**: the switch checks every ARP message against this table and
  **drops** those that don't match;
- **static ARP entries** for critical devices, and VLAN segmentation that limits the number of exposed
  machines.

<Callout type="field">
A classic symptom of an **IP address conflict**: a machine that "works, then stops working", at
random. Two devices answer ARP for the same IP, and the other machines' caches flip between their two
MACs. On a switch, `show mac address-table` and `show ip arp` let you track down both culprits.
</Callout>

## Troubleshooting

| Symptom | What the ARP cache shows | Lead |
|---|---|---|
| No communication with a machine in the same network | `FAILED` / `Incomplete` entry | machine off, wrong VLAN, cable, local firewall blocking |
| Nothing works beyond the local network | gateway shows `FAILED` | wrong gateway address, router interface down |
| Random outages | the MAC for a given IP keeps changing | IP address conflict, or ARP spoofing |
| It works after flushing the cache | old MAC still cached | hardware replaced, IP moved without a gratuitous ARP |

To watch ARP live, capture with the `arp` filter in Wireshark, or from the command line:

```bash
sudo tcpdump -i eth1 -n arp
```

<Callout type="note">
In IPv6, ARP no longer exists: it is replaced by **NDP** (Neighbor Discovery Protocol), which uses
ICMPv6 messages (*Neighbor Solicitation* and *Neighbor Advertisement*) sent as multicast rather than
broadcast. The principle stays the same.
</Callout>

## Key takeaways

- ARP finds **the MAC that matches an IP**, inside a local network.
- Request as **broadcast**, reply as **unicast**; the result is kept in the **ARP cache**.
- For a destination outside the network, you ARP for the **gateway**, never for the destination.
- **Gratuitous ARP** announces an address (conflict detection, gateway failover).
- ARP isn't authenticated: **DHCP Snooping + DAI** protect against spoofing.

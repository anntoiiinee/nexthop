In the previous chapter, we saw that a switch forms a single **broadcast domain**: every machine
receives the broadcasts of all the others. In our branch office, that means a visitor's laptop on the
guest Wi-Fi can directly reach the file server. <Term id="vlan" />s solve this problem without buying
one switch per use case.

## The principle

A VLAN splits one physical switch into several **logical switches**, sealed off from each other. Each
VLAN is identified by a number and forms its **own broadcast domain**: a frame received in VLAN 10 can
only leave through ports in VLAN 10.

The benefits:

- **Security**: guests, users and servers are separated. To go from one VLAN to another, traffic has
  to cross a router or a firewall, which can filter it.
- **Performance**: each broadcast stays within its VLAN.
- **Flexibility**: moving a workstation from one department to another means changing one line of
  configuration, not a cable.

Numbers range from **1 to 4094**. VLAN 1 exists by default: every port is in it at boot.

## Access ports and trunk ports

A switch port works in one of two modes:

| Mode | Connects | VLANs carried | Frames |
|---|---|---|---|
| **Access** | an end device (PC, printer, server) | just one | untagged: the device knows nothing about the VLAN |
| **Trunk** | another switch, a router, a hypervisor | several | tagged with the VLAN number (802.1Q) |

As soon as you have two switches, you need to carry several VLANs over a single cable: that is the
job of the **trunk**.

## The 802.1Q tag

On a trunk, how does SW2 know which VLAN a frame belongs to? SW1 inserts a 4-byte **tag**, defined by
the **IEEE 802.1Q** standard, right after the MAC addresses:

| Field | Size | Role |
|---|---|---|
| **TPID** | 16 bits | Always `0x8100`: it takes the place of the EtherType and announces "this frame is tagged". |
| **PCP** | 3 bits | Priority from 0 to 7, used for quality of service (voice goes before the rest). |
| **DEI** | 1 bit | Marks a frame that may be dropped first in case of congestion. |
| **VLAN ID** | 12 bits | The VLAN number. 12 bits give 4096 values; 0 and 4095 are reserved, hence **1 to 4094**. |

## The native VLAN

On a trunk, one VLAN can travel **untagged**: the **native VLAN** (VLAN 1 by default). It exists for
compatibility with devices that don't understand 802.1Q.

It must be **the same on both ends** of the trunk: otherwise, an untagged frame sent in SW1's native
VLAN lands in a different VLAN on SW2, connecting two VLANs that should be isolated.

<Callout type="warning">
Security best practices: keep no users in VLAN 1, choose an **unused** VLAN as the native VLAN (for
example 999), and allow on each trunk **only the VLANs that are needed**. Among other things, this
prevents double-tagging attacks (VLAN hopping).
</Callout>

## Configuration

Create the VLANs, put the machine-facing ports in access mode and configure the trunk.

```text title="Arista EOS"
vlan 10
   name USERS
vlan 20
   name GUEST-WIFI
vlan 30
   name SERVERS
!
interface Ethernet1
   description PC-accounting
   switchport mode access
   switchport access vlan 10
!
interface Ethernet48
   description trunk-to-SW2
   switchport mode trunk
   switchport trunk allowed vlan 10,20,30
   switchport trunk native vlan 999
```

```text title="Cisco IOS"
vlan 10
 name USERS
vlan 20
 name GUEST-WIFI
vlan 30
 name SERVERS
!
interface GigabitEthernet1/0/1
 description PC-accounting
 switchport mode access
 switchport access vlan 10
!
interface GigabitEthernet1/0/48
 description trunk-to-SW2
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 switchport trunk native vlan 999
 switchport nonegotiate
```

<Callout type="note">
On Cisco, `switchport nonegotiate` disables DTP, a proprietary protocol that can turn a port into a
trunk automatically. Setting the mode by hand is safer. On some older models, you also need
`switchport trunk encapsulation dot1q` before `switchport mode trunk`.
</Callout>

Port          Mode            Status          Native vlan
Et48          trunk           trunking        999

Port          Vlans allowed
Et48          10,20,30

Port          Vlans allowed and active in management domain
Et48          10,20,30
```

The most common mistakes: a VLAN created on one switch but **not on the other**, a VLAN missing from
the trunk's `allowed` list, or a native VLAN that differs on each end.

## Making VLANs talk to each other

VLANs are isolated at layer 2: for a PC in VLAN 10 to reach the server in VLAN 30, you have to
**route**, meaning go up to layer 3. There are two architectures:

- **router-on-a-stick**: a router connected to the switch by a trunk, with one subinterface per VLAN.
  Simple, but all inter-VLAN traffic goes through a single link;
- the **layer 3 switch**: the switch routes by itself thanks to one virtual interface per VLAN, the
  <Term id="svi" />. This is the standard solution today.

ip routing
!
interface Vlan10
   ip address 192.168.10.1/26
!
interface Vlan30
   ip address 192.168.10.97/28
```

The addresses used here (the `/26`, the `/28`) are explained in the IPv4 addressing chapter, and
routing itself in the static routing chapter. For now, remember: **one VLAN = one IP subnet = one gateway**.

## Key takeaways

- A VLAN creates an **isolated broadcast domain**; you have **1 to 4094** of them.
- **Access** port: one VLAN, untagged, towards a machine. **Trunk** port: several VLANs, 802.1Q
  tagged, between network devices.
- The 802.1Q tag adds **4 bytes**, including **12 bits** of VLAN number.
- The **native VLAN** travels untagged and must be the same on both ends.
- To go from one VLAN to another, you have to **route** (SVI on a layer 3 switch).

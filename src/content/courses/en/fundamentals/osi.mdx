When a colleague says "it's a layer 2 problem" or a firewall is sold as "layer 7", they are
referring to the **OSI model**. It is not a protocol: it is a frame of reference that splits a
network communication into 7 steps, from electrical signals all the way up to the application.

## Why a layered model?

Sending an e-mail involves dozens of things: a cable or Wi-Fi, addresses, routers, a reliable
connection, a message format… Putting all of them into a single block would be unmanageable. The
layered model **separates responsibilities**:

- each layer provides **a service** to the layer above and relies on the layer below;
- each layer only talks to **the same layer** on the other machine;
- you can change one layer without touching the others: replacing copper with fiber changes
  nothing for your web browser.

It works like the postal service: you write a letter (the content), put it in an envelope with an
address, and the post office sorts it and carries it by truck. The mail carrier doesn't read your
letter, and you don't pick the truck.

## The 7 layers

<OsiModel lang="en" />

The layers are often grouped into two families:

- **the lower layers (1 to 4)** carry the data: this is the network engineer's territory;
- **the upper layers (5 to 7)** deal with the application and its data. In practice, they are
  merged into a single "application" layer, as the TCP/IP model does.

| Layer | It answers the question… | Address used |
|---|---|---|
| 1. Physical | How do I transmit 0s and 1s over this medium? | none |
| 2. Data link | Which machine **on the local network** do I deliver this frame to? | <Term id="mac" /> address |
| 3. Network | Which way do I go to reach **another network**? | IP address |
| 4. Transport | Which **application** do I hand the data to, and did it all arrive? | port (80, 443, 22…) |
| 7. Application | What does the data contain and how should it be interpreted? | name (URL, e-mail…) |

## Encapsulation

When sending, data moves **down** the layers. Each layer adds its own header in front of the data
received from the layer above, without modifying it: this is **encapsulation**. The data unit
changes name at each level: it is the <Term id="pdu" />.

On reception, the reverse happens: each layer reads **its own** header, removes it, and passes the
rest to the layer above. This is **decapsulation**.

<Callout type="tip">
Remember this vocabulary above all: we say **frame** at layer 2, **packet** at layer 3 and
**segment** at layer 4. Saying "the switch received a packet" is understood by everyone, but
"a frame" is more accurate.
</Callout>

## Who works at which layer?

A network device doesn't need to go all the way up to layer 7 to do its job. It only reads what it
needs to decide where to send the data:

- a **switch** reads the Ethernet header and forwards the frame based on the destination MAC address;
- a **router** removes the Ethernet header, reads the IP address, picks the exit, then **builds a
  new frame** for the next link;
- a **stateful firewall** looks up to layer 4 (ports, connection state), a **next-generation
  firewall** all the way to layer 7 (application, URL, content).

## OSI or TCP/IP?

The Internet doesn't run on "the OSI protocols" but on the **TCP/IP** stack, which only has
4 layers (the diagram above shows how they map). Yet everyone keeps talking in OSI layers, because
the numbering has become a common language:

- "layer 2" = Ethernet, switches, VLANs, MAC addresses;
- "layer 3" = IP, routing;
- "layer 4" = <Term id="tcp" /> and <Term id="udp" />, ports;
- "layer 7" = the application (HTTP, DNS…).

## Troubleshooting layer by layer

Above all, the OSI model is used to **troubleshoot methodically**. Faced with "it doesn't work",
you check the layers **from the bottom up**: there's no point hunting for a DNS error if the cable
is unplugged.

| Layer | Questions to ask | Useful commands |
|---|---|---|
| 1. Physical | Is the link up? CRC errors, optical power too low? | `show interfaces status`, `show interfaces counters errors` |
| 2. Data link | Right VLAN? Is the MAC address learned? | `show vlan`, `show mac address-table` |
| 3. Network | Right IP, mask and gateway? Is there a route? | `ping`, `show ip route`, `traceroute` |
| 4. Transport | Is the port open? Is a firewall blocking? | `nc -zv server 443`, firewall logs |
| 7. Application | Does the service respond correctly? | `curl -v`, `dig`, application logs |

<Callout type="field">
In production, a large share of "network" incidents are solved at layer 1 or 2: a damaged cable, a
dirty optic, a port in the wrong VLAN. Starting from the bottom saves a huge amount of time, and
avoids blaming the network when the problem is in the application.
</Callout>

## Key takeaways

- The OSI model splits a communication into **7 layers**, each with its own role.
- When sending, each layer **adds its header** (encapsulation); when receiving, it removes it.
- The names to know: **bit, frame, packet, segment**.
- A switch works at **layer 2** (MAC), a router at **layer 3** (IP).
- To troubleshoot, go up the layers **from the bottom up**.

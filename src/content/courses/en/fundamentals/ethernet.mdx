Ethernet is the layer 1 and 2 technology used by almost every local network (<Term id="lan" />):
the RJ45 jacks in your office, the fiber links between switches, the servers in a data center.
Even Wi-Fi reuses its address format. Understanding Ethernet means understanding what **a switch**
does, the most common device in any network.

## Media and speeds

Ethernet comes in many variants, named after the speed and the medium. The name `1000BASE-T`
reads: 1000 Mb/s, baseband transmission (BASE), over twisted pairs (T).

| Standard | Speed | Medium | Common use |
|---|---|---|---|
| 100BASE-TX | 100 Mb/s | copper, RJ45 | IP phones, old equipment |
| 1000BASE-T | 1 Gb/s | copper, RJ45 (Cat 5e/6) | workstations, printers |
| 10GBASE-SR | 10 Gb/s | multimode fiber, SFP+ | servers, links between switches |
| 25GBASE-SR | 25 Gb/s | multimode fiber, SFP28 | data center servers |
| 100GBASE-SR4 / LR4 | 100 Gb/s | fiber, QSFP28 | spine/leaf links, network core |

Copper is limited to **100 meters**; beyond that, you switch to fiber (a few hundred meters over
multimode, kilometers over single-mode).

## The MAC address

Every network card has a **48-bit** (6-byte) <Term id="mac" /> address, written in hexadecimal.
It identifies the interface on the local network.

<PacketFormat
  cols={12}
  rows={[
    { fields: [
      { label: '00 : 1c : 73', sub: 'OUI · 3 bytes', span: 6, tone: 'amber', mono: true },
      { label: 'aa : bb : cc', sub: 'card identifier · 3 bytes', span: 6, tone: 'sky', mono: true },
    ] },
  ]}
  minWidth="28rem"
  caption="A MAC address: the first 3 bytes identify the vendor, the next 3 the card."
/>

- The first 3 bytes form the <Term id="oui" />, assigned by the IEEE to each vendor. `00:1c:73`
  belongs to Arista: seeing this address in a table already tells you what kind of device it is.
- The next 3 bytes are chosen by the vendor so that every card is unique.

Two bits of the first byte have a special meaning:

<PacketFormat
  cols={8}
  rows={[
    { label: '1st byte', fields: [
      { label: 'b7', sub: '0', mono: true }, { label: 'b6', sub: '0', mono: true },
      { label: 'b5', sub: '0', mono: true }, { label: 'b4', sub: '0', mono: true },
      { label: 'b3', sub: '0', mono: true }, { label: 'b2', sub: '0', mono: true },
      { label: 'U/L', sub: '0 = universal', tone: 'violet' },
      { label: 'I/G', sub: '0 = unicast', tone: 'rose' },
    ] },
  ]}
  minWidth="34rem"
  caption="The I/G bit tells unicast from multicast, the U/L bit a vendor address from a locally administered one."
/>

- **I/G** (least significant bit): `0` = address of **one** machine (unicast), `1` = **group**
  address (multicast or broadcast).
- **U/L**: `0` = universal address (the vendor's), `1` = locally administered address, for example
  generated by a virtual machine or by a phone hiding its real address.

Depending on the device, the same address is written in several ways. They all refer to the same card:

| Format | Example | Used by |
|---|---|---|
| Colons | `00:1c:73:aa:bb:cc` | Linux, Arista (display) |
| Dashes | `00-1C-73-AA-BB-CC` | Windows |
| Dots (groups of 4) | `001c.73aa.bbcc` | Cisco, Arista (MAC tables) |

<Callout type="tip">
To convert from one format to another, remove all separators: you are left with 12 hexadecimal
characters, always the same ones.
</Callout>

## The Ethernet frame

Layer 3 data (an IP packet) is placed inside an Ethernet **frame**. Here is the format used
everywhere today, called Ethernet II:

<PacketFormat
  cols={13}
  rows={[
    { fields: [
      { label: 'Preamble + SFD', sub: '8 bytes', span: 2, dashed: true },
      { label: 'Destination MAC', sub: '6 bytes', span: 2, tone: 'amber' },
      { label: 'Source MAC', sub: '6 bytes', span: 2, tone: 'amber' },
      { label: 'EtherType', sub: '2 bytes', span: 1, tone: 'violet' },
      { label: 'Data (IP packet…)', sub: '46 to 1500 bytes', span: 5, tone: 'emerald' },
      { label: 'FCS', sub: '4 bytes', span: 1, tone: 'rose' },
    ] },
  ]}
  minWidth="40rem"
  caption="An Ethernet II frame. The preamble synchronizes the transmission (layer 1): it does not show up in captures."
/>

| Field | Role |
|---|---|
| **Destination MAC** | Who the frame is for. Placed first so that the switch can start deciding very early. |
| **Source MAC** | Who sends the frame. This is the field the switch **learns** from. |
| **EtherType** | Which protocol is carried: `0x0800` IPv4, `0x86DD` IPv6, `0x0806` <Term id="arp" />, `0x8100` 802.1Q VLAN. |
| **Data** | The layer 3 packet. At least 46 bytes (padded if needed), at most 1500: this is the standard <Term id="mtu" />. |
| **FCS** | Check code (<Term id="fcs" />) computed over the whole frame. The receiver recomputes it: if it doesn't match, the frame is dropped. |

A frame is therefore between **64 and 1518 bytes** long (without the preamble).

<Callout type="field">
A **CRC** or **FCS** error counter increasing on an interface almost always points to a physical
problem: damaged cable, badly crimped connector, dirty or incompatible optic. It is layer 1 talking,
not the configuration.
</Callout>

## Unicast, broadcast and multicast

The destination address tells how many machines should receive the frame:

| Type | Destination address | Received by | Example |
|---|---|---|---|
| **Unicast** | a card's address, I/G bit at 0 | a single machine | most traffic |
| **Broadcast** | `ff:ff:ff:ff:ff:ff` | every machine on the local network | ARP request, DHCP Discover |
| **Multicast** | I/G bit at 1, for example `01:00:5e:…` | machines subscribed to a group | IPTV, routing protocols |

## How a switch learns

A switch knows nothing when it boots. It builds its **MAC address table** (also called the CAM
table) by watching traffic. Its rule fits in three lines:

1. **Learn**: for every frame received, it notes "the source MAC address is behind this port".
2. **Forward**: if the destination MAC address is in the table, it sends the frame only out of the
   matching port.
3. **Flood**: if the destination is unknown (or it is a broadcast), it sends a copy out of **every
   port** except the one it came in on.

Let's follow an exchange between A and B on a switch that has just booted.

**floods** the frame to Et2 and Et3. C didn't ask for it: its network card sees that the destination
address isn't its own and drops it.

| VLAN | MAC address | Port |
|---|---|---|
| 1 | `0200.0000.000a` | Et1 |

This time, the switch learns `…:0b → Et2`, and it **knows** the destination `…:0a`: the frame goes
out of Et1 only. From now on, all traffic between A and B is switched directly.

| VLAN | MAC address | Port |
|---|---|---|
| 1 | `0200.0000.000a` | Et1 |
| 1 | `0200.0000.000b` | Et2 |

An entry that is no longer used disappears after an inactivity timer, **300 seconds** by default:
the **aging time**. If a machine moves to another port, its address is simply relearned on the new
port with its next frame.

## Broadcast domain

A broadcast is flooded out of **every port** of the switch, and from one switch to the next. The set
of machines reached by the same broadcast forms a **broadcast domain**.

The bigger the domain, the more broadcasts each machine receives that don't concern it, and the
bigger the impact of a failure or a loop. That is exactly the problem **VLANs** solve, in the next
chapter.

<Callout type="note">
Old **hubs** copied every frame to every port, with no MAC table, and only one device could transmit
at a time (half duplex, collisions). Modern switches work in **full duplex**: each port sends and
receives at the same time, and collisions no longer exist.
</Callout>

## On a real switch

The MAC table is displayed with the same command on Arista EOS and Cisco IOS:

```text title="SW1#show mac address-table"
          Mac Address Table
------------------------------------------------------------------

Vlan    Mac Address       Type        Ports      Moves   Last Move
----    -----------       ----        -----      -----   ---------
   1    0200.0000.000a    DYNAMIC     Et1        1       0:00:42 ago
   1    0200.0000.000b    DYNAMIC     Et2        1       0:00:41 ago
Total Mac Addresses for this criterion: 2
```

A few useful variants:

```text
show mac address-table address 0200.0000.000b   ! where is this machine?
show mac address-table interface Ethernet1      ! who is behind this port?
clear mac address-table dynamic                 ! flush the table (it rebuilds itself)
```

<Callout type="field">
To find the port of a device when you only know its IP: a `ping` from the network (so that it
sends something), then `show ip arp` on the gateway to get its MAC, and finally
`show mac address-table address …` from switch to switch until you reach a port that isn't a link
to another switch.
</Callout>

## Key takeaways

- A MAC address is **48 bits**: 3 vendor bytes (OUI) and 3 card bytes.
- The Ethernet frame contains **destination MAC, source MAC, EtherType, data and FCS**; the standard
  MTU is **1500 bytes**.
- A switch **learns** from the source address, **forwards** using the destination address, and
  **floods** when it doesn't know.
- A broadcast (`ff:ff:ff:ff:ff:ff`) reaches the whole **broadcast domain**.

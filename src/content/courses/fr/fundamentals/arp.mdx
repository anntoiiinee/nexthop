On a maintenant deux types d'adresses : l'adresse **IP** pour savoir **où** aller (couche 3), et
l'adresse **MAC** pour livrer la trame sur le réseau local (couche 2). Mais quand PC1 veut joindre
`192.168.10.20`, il ne connaît que son IP. Pour construire la trame Ethernet, il lui faut sa MAC.
Le protocole qui fait le lien entre les deux, c'est <Term id="arp" /> (RFC 826).

## Le problème

Sans adresse MAC de destination, pas de trame, donc pas de communication, même dans le même
réseau. ARP sert exactement à répondre à la question : « **quelle MAC possède cette IP ?** »

## L'échange ARP

ARP fonctionne en deux temps :

1. **La requête**, envoyée en **broadcast** (`ff:ff:ff:ff:ff:ff`) : toutes les machines du VLAN la
   reçoivent. Elle dit : « Qui a 192.168.10.20 ? Répondez à 192.168.10.10 ».
2. **La réponse**, envoyée en **unicast** par la seule machine concernée : « 192.168.10.20, c'est
   moi, ma MAC est `02:00:00:00:00:20` ».

Au passage, chacun apprend quelque chose :

- **PC1** note la MAC de PC2 dans son **cache ARP** ;
- **PC2** note aussi la MAC de PC1 (elle figure dans la requête) : il en aura besoin pour répondre ;
- **le switch** apprend la position de PC1 grâce à la requête, et celle de PC2 grâce à la réponse.

## Le paquet ARP

Un message ARP est transporté directement dans une trame Ethernet, avec l'EtherType `0x0806`.
Il n'y a pas d'en-tête IP : ARP fonctionne **uniquement à l'intérieur d'un réseau local**.

| Champ | Requête de PC1 | Réponse de PC2 |
|---|---|---|
| MAC destination (Ethernet) | `ff:ff:ff:ff:ff:ff` (broadcast) | `02:00:00:00:00:10` (PC1) |
| Opération | 1 (request) | 2 (reply) |
| MAC émetteur | `02:00:00:00:00:10` | `02:00:00:00:00:20` |
| IP émetteur | `192.168.10.10` | `192.168.10.20` |
| MAC cible | `00:00:00:00:00:00` | `02:00:00:00:00:10` |
| IP cible | `192.168.10.20` | `192.168.10.10` |

## Le cache ARP

Faire une requête avant chaque paquet serait très lent. Chaque machine garde donc les réponses
dans un **cache ARP** (ou table de voisinage), avec une durée de vie limitée :

```text title="Linux : ip neigh"
192.168.10.1 dev eth1 lladdr 00:1c:73:aa:bb:01 REACHABLE
192.168.10.20 dev eth1 lladdr 02:00:00:00:00:20 STALE
192.168.10.99 dev eth1 FAILED
```

```text title="Windows : arp -a"
Interface : 192.168.10.10 --- 0x7
  Adresse Internet      Adresse physique      Type
  192.168.10.1          00-1c-73-aa-bb-01     dynamique
  192.168.10.20         02-00-00-00-00-20     dynamique
```

```text title="R1#show ip arp"
Address         Age (sec)  Hardware Addr   Interface
192.168.10.10     0:01:12  0200.0000.0010  Ethernet1
192.168.10.20     0:00:45  0200.0000.0020  Ethernet1
192.168.10.121    0:03:02  001c.73cc.dd02  Ethernet2
```

Les durées varient beaucoup : de quelques secondes à quelques minutes sur Linux et Windows (qui
revérifient régulièrement leurs entrées), **4 heures** par défaut sur les routeurs et switches
Cisco et Arista. Une entrée `FAILED` (Linux) ou `Incomplete` (Cisco)
signifie qu'une requête est partie mais que **personne n'a répondu**.

<Callout type="tip">
`ip neigh flush all` (Linux) ou `arp -d *` (Windows, en administrateur) vident le cache. Utile
après avoir changé une carte réseau ou déplacé une adresse IP d'une machine à une autre.
</Callout>

## Et si la destination est dans un autre réseau ?

C'est le point qui piège le plus de débutants : **une machine ne fait jamais d'ARP pour une
adresse qui n'est pas dans son réseau.** Une requête ARP est un broadcast ; elle ne traverse pas
les routeurs. Pour joindre `172.16.20.10` au siège, PC1 fait une requête ARP pour sa
**passerelle** :

La trame envoyée aura donc pour destination la **MAC de R1**, et pour IP de destination
`172.16.20.10`. C'est ce qu'on détaille au chapitre suivant sur le routage, où chaque routeur
refait la même chose avec le prochain saut.

## L'ARP gratuit

Un **ARP gratuit** (gratuitous ARP) est une annonce que personne n'a demandée : une machine
diffuse « 192.168.10.1, c'est moi, ma MAC est … ». On l'utilise :

- **au démarrage ou au changement d'adresse** : pour vérifier que personne d'autre n'utilise
  déjà cette IP (détection de conflit) ;
- **lors d'une bascule de passerelle redondante** (<Term id="vrrp" />, HSRP) : le routeur qui
  devient actif annonce l'adresse IP de la passerelle avec sa MAC. Toutes les machines mettent
  leur cache à jour, et les switches leur table MAC, sans attendre l'expiration des entrées.

## La faiblesse d'ARP : l'usurpation

ARP date de 1982 et ne prévoit **aucune authentification** : une machine accepte une réponse ARP
sans vérifier qui l'envoie, même sans avoir posé de question. Un attaquant présent dans le VLAN
peut donc envoyer de fausses réponses, c'est l'**usurpation ARP** (ARP spoofing ou poisoning) :

Les protections, sur les switches d'accès :

- **DHCP Snooping** : le switch observe les échanges <Term id="dhcp" /> et retient quelle IP a été
  attribuée à quelle MAC, sur quel port ;
- **Dynamic ARP Inspection (DAI)** : le switch compare chaque message ARP à cette table et **jette**
  ceux qui ne correspondent pas ;
- des **entrées ARP statiques** pour les équipements critiques, et une segmentation en VLAN qui
  limite le nombre de machines exposées.

<Callout type="field">
Un symptôme classique de **conflit d'adresse IP** : une machine qui « marche, puis ne marche plus »,
de façon aléatoire. Deux équipements répondent à l'ARP pour la même IP, et le cache des autres
machines oscille entre leurs deux MAC. Sur un switch, `show mac address-table` et `show ip arp`
permettent de retrouver les deux coupables.
</Callout>

## Dépanner

| Symptôme | Ce que montre le cache ARP | Piste |
|---|---|---|
| Aucune communication avec une machine du même réseau | entrée `FAILED` / `Incomplete` | machine éteinte, mauvais VLAN, câble, firewall local qui bloque |
| Plus rien au-delà du réseau local | passerelle en `FAILED` | mauvaise adresse de passerelle, interface du routeur down |
| Coupures aléatoires | la MAC d'une même IP change | conflit d'adresse IP, ou usurpation ARP |
| Ça marche après un `flush` du cache | ancienne MAC conservée | matériel remplacé, IP déplacée sans ARP gratuit |

Pour voir ARP en direct, une capture avec le filtre `arp` dans Wireshark, ou en ligne de commande :

```bash
sudo tcpdump -i eth1 -n arp
```

<Callout type="note">
En IPv6, ARP n'existe plus : il est remplacé par **NDP** (Neighbor Discovery Protocol), qui
utilise des messages ICMPv6 (*Neighbor Solicitation* et *Neighbor Advertisement*) envoyés en
multicast plutôt qu'en broadcast. Le principe reste le même.
</Callout>

## À retenir

- ARP trouve **la MAC qui correspond à une IP**, à l'intérieur d'un réseau local.
- Requête en **broadcast**, réponse en **unicast** ; le résultat est gardé dans le **cache ARP**.
- Pour une destination hors du réseau, on fait l'ARP de la **passerelle**, jamais de la destination.
- L'**ARP gratuit** annonce une adresse (détection de conflit, bascule de passerelle).
- ARP n'est pas authentifié : **DHCP Snooping + DAI** protègent contre l'usurpation.

Au chapitre précédent, on a vu qu'un switch forme un seul **domaine de broadcast** : chaque
machine reçoit les broadcasts de toutes les autres. Dans notre agence, cela veut dire que le
portable d'un visiteur sur le Wi-Fi invités peut joindre directement le serveur de fichiers.
Les <Term id="vlan" /> règlent ce problème sans acheter un switch par usage.

## Le principe

Un VLAN découpe un switch physique en plusieurs **switches logiques**, étanches entre eux. Chaque
VLAN est identifié par un numéro et forme son **propre domaine de broadcast** : une trame reçue
dans le VLAN 10 ne peut ressortir que par des ports du VLAN 10.

Les bénéfices :

- **Sécurité** : les invités, les utilisateurs et les serveurs sont séparés. Pour passer d'un
  VLAN à l'autre, il faut traverser un routeur ou un firewall, qui peut filtrer.
- **Performance** : chaque broadcast reste dans son VLAN.
- **Souplesse** : déplacer un poste d'un service à l'autre, c'est changer une ligne de
  configuration, pas un câble.

Les numéros vont de **1 à 4094**. Le VLAN 1 existe par défaut : tous les ports y sont au démarrage.

## Ports access et ports trunk

Un port de switch fonctionne selon l'un de ces deux modes :

| Mode | Raccorde | VLAN transportés | Trames |
|---|---|---|---|
| **Access** | un équipement final (PC, imprimante, serveur) | un seul | sans étiquette : l'équipement ignore tout du VLAN |
| **Trunk** | un autre switch, un routeur, un hyperviseur | plusieurs | étiquetées avec le numéro de VLAN (802.1Q) |

Dès qu'on a deux switches, il faut faire passer plusieurs VLAN sur un seul câble : c'est le rôle
du **trunk**.

## L'étiquette 802.1Q

Sur un trunk, comment SW2 sait-il à quel VLAN appartient une trame ? SW1 y insère une
**étiquette** (tag) de 4 octets, définie par la norme **IEEE 802.1Q**, juste après les adresses MAC :

| Champ | Taille | Rôle |
|---|---|---|
| **TPID** | 16 bits | Toujours `0x8100` : il occupe la place de l'EtherType et annonce « cette trame est étiquetée ». |
| **PCP** | 3 bits | Priorité de 0 à 7, utilisée pour la qualité de service (la voix passe avant le reste). |
| **DEI** | 1 bit | Indique une trame qui peut être jetée en priorité en cas de congestion. |
| **VLAN ID** | 12 bits | Le numéro de VLAN. 12 bits donnent 4096 valeurs ; 0 et 4095 sont réservés, d'où **1 à 4094**. |

## Le VLAN natif

Sur un trunk, un VLAN peut circuler **sans tag** : c'est le **VLAN natif** (le VLAN 1 par
défaut). Il existe pour la compatibilité avec des équipements qui ne comprennent pas 802.1Q.

Il doit être **identique des deux côtés** du trunk : sinon, une trame non étiquetée envoyée
dans le VLAN natif de SW1 arrive dans un autre VLAN sur SW2, ce qui fait communiquer deux VLAN
qui devraient être isolés.

<Callout type="warning">
Bonnes pratiques de sécurité : ne laissez aucun utilisateur dans le VLAN 1, choisissez comme VLAN
natif un VLAN **inutilisé** (par exemple 999), et n'autorisez sur chaque trunk **que les VLAN
nécessaires**. Cela évite notamment les attaques par double étiquette (VLAN hopping).
</Callout>

## Configuration

On crée les VLAN, on place les ports des machines en mode access et on configure le trunk.

```text title="Arista EOS"
vlan 10
   name UTILISATEURS
vlan 20
   name WIFI-INVITES
vlan 30
   name SERVEURS
!
interface Ethernet1
   description PC-comptabilite
   switchport mode access
   switchport access vlan 10
!
interface Ethernet48
   description trunk-vers-SW2
   switchport mode trunk
   switchport trunk allowed vlan 10,20,30
   switchport trunk native vlan 999
```

```text title="Cisco IOS"
vlan 10
 name UTILISATEURS
vlan 20
 name WIFI-INVITES
vlan 30
 name SERVEURS
!
interface GigabitEthernet1/0/1
 description PC-comptabilite
 switchport mode access
 switchport access vlan 10
!
interface GigabitEthernet1/0/48
 description trunk-vers-SW2
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 switchport trunk native vlan 999
 switchport nonegotiate
```

<Callout type="note">
Sur Cisco, `switchport nonegotiate` désactive DTP, un protocole propriétaire qui peut transformer
un port en trunk automatiquement. Fixer le mode à la main est plus sûr. Sur certains anciens
modèles, il faut aussi ajouter `switchport trunk encapsulation dot1q` avant `switchport mode trunk`.
</Callout>

Les erreurs les plus fréquentes : un VLAN créé sur un switch mais **pas sur l'autre**, un VLAN
absent de la liste `allowed` du trunk, ou un VLAN natif différent des deux côtés.

## Faire communiquer les VLAN

Les VLAN sont isolés en couche 2 : pour qu'un PC du VLAN 10 joigne le serveur du VLAN 30, il faut
**router**, donc passer en couche 3. Deux architectures existent :

- le **router-on-a-stick** : un routeur relié au switch par un trunk, avec une sous-interface
  par VLAN. Simple, mais tout le trafic entre VLAN passe par un seul lien ;
- le **switch de niveau 3** : le switch route lui-même grâce à une interface virtuelle par VLAN,
  la <Term id="svi" />. C'est la solution standard aujourd'hui.

IPv4, et le routage lui-même au chapitre sur le routage statique. Retenez pour l'instant : **un VLAN = un
sous-réseau IP = une passerelle**.

## À retenir

- Un VLAN crée un **domaine de broadcast isolé** ; on en dispose de **1 à 4094**.
- Port **access** : un VLAN, sans tag, vers une machine. Port **trunk** : plusieurs VLAN,
  étiquetés 802.1Q, entre équipements réseau.
- Le tag 802.1Q ajoute **4 octets** dont **12 bits** de numéro de VLAN.
- Le **VLAN natif** circule sans tag et doit être identique des deux côtés.
- Pour passer d'un VLAN à l'autre, il faut **router** (SVI sur un switch de niveau 3).

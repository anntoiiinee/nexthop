Un switch de 48 ports, des câbles dans tous les sens, et une question simple : **qu'est-ce qui est
branché sur le port 23 ?** Plutôt que de suivre le câble à la main dans la baie, on interroge le
switch. Il le sait, grâce à <Term id="lldp" /> ou à son équivalent Cisco, <Term id="cdp" />.

## Le principe

Chaque équipement envoie régulièrement, sur chacun de ses ports, une petite trame qui dit
**qui il est** : son nom, le port par lequel il envoie, son modèle, son adresse de gestion…
Son voisin direct la reçoit et range ces informations dans une **table des voisins**.

Deux propriétés importantes :

- les annonces sont envoyées vers une **adresse multicast spéciale** que les switches ne
  retransmettent jamais : on ne découvre que ses **voisins directs**, à un seul saut ;
- elles sont **indépendantes de l'IP** : elles fonctionnent même sur un port sans adresse, dans
  n'importe quel VLAN. C'est ce qui en fait un excellent outil de diagnostic de couche 2.

## LLDP : le standard

**LLDP** (Link Layer Discovery Protocol) est défini par la norme **IEEE 802.1AB**. Tous les
constructeurs le supportent : Arista, Cisco, Juniper, mais aussi les serveurs Linux (démon `lldpd`),
les hyperviseurs, les téléphones IP et les bornes Wi-Fi.

| Paramètre | Valeur par défaut |
|---|---|
| Adresse de destination | `01:80:c2:00:00:0e` (multicast, jamais retransmise) |
| EtherType | `0x88cc` |
| Envoi | toutes les **30 secondes** |
| Durée de validité (TTL) | **120 secondes** : sans nouvelle annonce, le voisin disparaît de la table |

### Une trame faite de TLV

Les informations d'une trame LLDP sont rangées en **TLV** (Type, Longueur, Valeur) : chaque
information a un type, une taille et un contenu. Les trois premiers TLV sont obligatoires.

Une extension, **LLDP-MED** (Media Endpoint Discovery), ajoute des TLV pour la téléphonie : le
switch annonce au téléphone IP **le VLAN voix** à utiliser, et le téléphone annonce sa consommation
électrique (PoE).

## CDP : la version Cisco

**CDP** (Cisco Discovery Protocol) est l'ancêtre propriétaire de LLDP, présent sur tous les
équipements Cisco. Le principe est identique.

| | LLDP | CDP |
|---|---|---|
| Norme | IEEE 802.1AB, multi-constructeur | propriétaire Cisco |
| Adresse de destination | `01:80:c2:00:00:0e` | `01:00:0c:cc:cc:cc` |
| Intervalle / validité | 30 s / 120 s | 60 s / 180 s |
| Activé par défaut | Arista EOS : oui · Cisco IOS : non | Cisco IOS : oui |
| Téléphonie | LLDP-MED | natif (VLAN voix, PoE) |

Alors, **LLDP ou CDP ?** Dans un réseau multi-constructeur, **LLDP**, puisque c'est le seul que
tout le monde parle. Dans un réseau 100 % Cisco, CDP fonctionne très bien, mais activer LLDP en
plus ne coûte rien et prépare l'arrivée d'autres équipements. Les deux peuvent tourner en même temps.

<Callout type="note">
Arista EOS ne parle pas CDP en natif : face à un switch Cisco, activez LLDP côté Cisco
(`lldp run`) et les deux se verront.
</Callout>

## Configuration

```text title="Arista EOS"
lldp run                          ! activé par défaut
lldp timer 30
lldp hold-time 120
!
interface Ethernet1
   description vers-internet
   no lldp transmit               ! ne pas s'annoncer vers l'extérieur
   no lldp receive
```

```text title="Cisco IOS"
cdp run                           ! activé par défaut
lldp run                          ! désactivé par défaut : à activer
!
interface GigabitEthernet1/0/1
 description vers-internet
 no cdp enable
 no lldp transmit
 no lldp receive
```

## À quoi ça sert en production

- **Retrouver un équipement** : « le serveur srv-01 est branché sur SW1, port Et20 », sans
  descendre en salle serveur.
- **Vérifier le câblage** : on compare les voisins LLDP réels au plan de câblage prévu. Les outils
  d'automatisation le font en masse : un câble inversé entre deux ports saute immédiatement aux yeux.
- **Documenter automatiquement** : des scripts ou des outils comme NetBox reconstruisent la
  topologie complète à partir des tables LLDP de tous les switches.
- **Configurer les téléphones IP** : LLDP-MED ou CDP leur donnent le VLAN voix sans configuration manuelle.

<Callout type="field">
Lors d'une migration ou d'un déploiement de fabric, la validation des voisins LLDP fait partie des
premiers contrôles automatisés : si chaque lien relie bien le port attendu au port attendu, une
grande partie des problèmes de « ça ne monte pas » disparaît avant même de regarder le routage.
</Callout>

## Et la sécurité ?

LLDP et CDP diffusent des informations utiles… y compris à un attaquant : nom de l'équipement,
modèle exact, version logicielle (et donc ses failles connues), adresse IP de gestion. D'où une
règle simple : **désactiver LLDP et CDP sur les ports qui ne sont pas de confiance** (liens vers
Internet ou vers un opérateur, ports dans les espaces publics), et les garder sur les liens
internes, où ils rendent de grands services.

## Dans le lab

Le lab du chapitre sur le routage statique s'y prête bien : une fois déployé, tapez
`show lldp neighbors` sur `r2`. Vous verrez `r1` et `r3`, avec le port de chacun, alors qu'aucune
route n'est encore configurée : LLDP ne dépend pas de l'IP.

## À retenir

- LLDP et CDP annoncent l'**identité d'un équipement à ses voisins directs**, à un seul saut.
- **LLDP** (IEEE 802.1AB) est le standard multi-constructeur ; **CDP** est l'équivalent Cisco.
- Une annonce LLDP est composée de **TLV** : Chassis ID, Port ID et TTL sont obligatoires.
- `show lldp neighbors` (ou `show cdp neighbors`) : qui est branché sur quel port.
- Désactivez-les sur les ports **non fiables** : ils révèlent modèle et version.

On remonte maintenant en couche 3 avec l'**adressage IPv4**.
